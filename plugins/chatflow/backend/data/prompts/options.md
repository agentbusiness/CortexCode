Under each idea above the host listed what it found: code in this repository, earlier notes, and work elsewhere. Choose the options the user decides between. Nothing is changed.

1. `critique`: one item per idea, in order: `keep` or `drop`, and why in one line: a constraint it breaks, its cost, its risk, or what the findings show (done elsewhere already, with the problems reported there).
2. `options`: the two or three strongest kept ideas, best first. For each:
- `idea`: its number.
- `name` and `mechanism`: as above, made precise by the findings.
- `why`: how it meets the criteria.
- `grounding`: the findings it builds on.
- `prior_art`: where it is done already and what went wrong there, or "not found".
- `cost`: the files and parts it changes, and any new dependency.
- `risk`: what could go wrong.
- `settle_by`: the cheapest experiment or check that shows early whether it works.
3. `radical`: one more idea that drops an assumption every option keeps, not a bigger option: `drops` names the assumption, `buys` what dropping it gains, `wins_if` what must be true for it to win.
4. `recommend`: the idea number of the option you recommend; `because`: why; `would_change_if`: the fact that would change the choice.

Example `critique` item: idea 5, `drop`, "removing the index breaks the 100 ms limit the user set".
