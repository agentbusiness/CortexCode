Write a plan for the work the conversation arrived at, from the request, the project description and what the conversation shows, never from what you remember of similar code elsewhere (its usual tests, names or answers); nothing is changed yet. Where the user changed their mind during the conversation, the latest user message wins. When the user asked for code, the tasks change code: a document or a run alone is not that work. Each task finds its own code when it runs. Plan only what the user asked, the simplest way that does it, with what the language, its standard library and the project already provide: no task for work the user did not ask for. `note`: one short sentence telling the user what to review, and naming what more should be done that the user did not ask for.
